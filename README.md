# Nordic Portfolio Showcase

Personal portfolio site for **Rickard Sörlin** — AI Product Manager (industrial platforms, SCADA
& applied AI). Live at **[rickardsorlin.se](https://rickardsorlin.se)**.

A Nordic-themed site: an aurora backdrop, a scroll-driven career timeline on the landing page, and
case pages for selected projects.

## Pages

| Route | Content |
| --- | --- |
| `/` | Home — hero, selected projects and the career timeline |
| `/projects`, `/projects/:slug` | Project overview and one case page per project |
| `/education` | Education, certifications and capabilities |
| `/about` | About |
| `/cv` | Web CV, with a downloadable PDF |
| `/contact` | Contact |

`/journey` is the old landing page and redirects to `/`, so existing links keep working.

## Stack

- [TanStack Start](https://tanstack.com/start) (SSR) with file-based TanStack Router, React 19
- Tailwind CSS 4, shadcn/ui (Radix), `motion` for animation
- Vite 8, built with Nitro's `node-server` preset
- Bun to install and build, Node 22 to run in production

## Development

```sh
bun install        # bun.lock is the lockfile; `npm i` also works but ignores it
bun run dev        # vite dev server
```

| Script | What it does |
| --- | --- |
| `dev` | Start the dev server |
| `build` | Production build into `.output/` |
| `start` | Run the built server: `node .output/server/index.mjs` (port 3000) |
| `preview` | Preview a build with Vite |
| `lint` / `format` | ESLint / Prettier |

## Project layout

| Path | Purpose |
| --- | --- |
| `src/routes/` | One file per route (see [src/routes/README.md](src/routes/README.md)). Root layout is `__root.tsx`. |
| `src/content/` | **All site copy and data** — profile, projects, timeline, education, CV. Most content changes happen here, not in components. |
| `src/components/` | Site components (`ui/` holds the shadcn primitives) |
| `src/routeTree.gen.ts` | Generated by the router plugin — don't edit by hand |
| `public/assets/` | Images and the CV PDF, served at `/assets/…` |
| `.lovable/plan/` | Plans saved by the Lovable editor |
| `roadmap.md` | What's been done and what's next |

The web CV renders from `src/content/cv.ts`; the downloadable PDF is
`public/assets/rickard-sorlin-cv.pdf`. Update both together so they don't drift apart.

## Working with Lovable

This project is built and edited in [Lovable](https://lovable.dev/projects/d04d78f9-3f69-4856-88ac-5033fb5f0581);
most commits on `main` are synced from the editor, and pushes to `main` sync back into it.

**Never force-push, rebase, or amend/squash commits that are already pushed to `main`** — that
rewrites history on Lovable's side and can lose project history there. Only move forward. See
[AGENTS.md](AGENTS.md).

## Docker and self-hosting

The [Dockerfile](Dockerfile) builds in two stages — Bun builds the app, then a small
`node:22-alpine` image runs `.output/server/index.mjs` as a non-root user on port 3000.

```sh
docker compose up --build    # then open http://127.0.0.1:3000
```

[docker-compose.yml](docker-compose.yml) binds the port to **loopback only** and defines a
healthcheck. The container is meant to sit behind a reverse proxy that terminates HTTPS; it is
not exposed directly.

### Deploying

Production runs as a container on a Synology NAS behind Synology's reverse proxy. **Pushing to
`main` does not deploy** — deployment is a separate, explicit step. [update.sh](update.sh), run
from the release checkout on the NAS, does the whole job:

1. refuses to run if the checkout has local changes, then `git pull --ff-only`
2. tags the running image as `rickard-portfolio:previous` (rollback point)
3. `docker compose build` and `up -d`
4. verifies the key routes respond, and **rolls back automatically** if any don't

The full runbook — checking what's live, running the deploy, verifying afterwards, and what not
to do — is in [CLAUDE.md](CLAUDE.md#deploying-to-the-nas).
